# Skills depth beats skills breadth

**Claim**: Lopopolo's team centralizes leverage around 5–10 skills and keeps making those skills better, rather than sprawling to thousands of niche skills. The skill hides all local dev-tool complexity from the human; the agent just invokes it.

**Why it matters**: Infrastructure inside a repo changes constantly. A deep skill absorbs that churn. Lopopolo's team migrated from direct Chrome DevTools Protocol to a daemon-based architecture and *he didn't notice for three weeks* because the skill abstracted it. Breadth = surface area to maintain. Depth = compound leverage.

**Signals a skill is the right depth**:
- The human never has to know the underlying tool changed
- The agent gets a stable invocation contract
- Updates to the skill immediately improve every agent that calls it

**For SISO**: Validates the post-2026-04-16 cleanup (53 agents → 11). The decision pattern extends to skills too: prefer to improve an existing skill than add a new one. Our `superpowers:*` and `siso-*` families should consolidate aggressively.
