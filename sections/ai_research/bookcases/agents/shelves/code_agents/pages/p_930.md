# Harness = just-in-time prompt injection, nothing more

**Claim**: A good harness surfaces instructions to the model at the right time. It is not a shell around the app, not a pipeline orchestrator, not a ticket system. It is a mechanism for injecting the right text into the agent's context window at the exact moment that text is useful.

**Why it matters**: This reframes what "harness engineering" actually is. Context is never obsoleted by model improvements — the model must always be told task requirements and guardrails. But *when* you inject those instructions determines throughput. Front-load everything → overwhelmed agent. Inject at the right moment → surgical prompt, the model self-heals.

**The injection surfaces Lopopolo uses**:
- `AGENTS.md` / `CLAUDE.md` (load-time)
- Skills (discovery-time)
- Rules files (always-on)
- Lint error messages (emit-time)
- Test failures (verify-time)
- Reviewer agents posting PR comments (post-push)
- Plan mode / exec plans (planning-time)

**Example**: Instead of pre-loading "break React components into stateless pieces," let the agent prototype freely. Then at lint time emit: "components must be under N lines and stateless where possible." The agent sees a new instruction, refactors, ships.

**For SISO Bifrost**: Our injection surfaces are: `TASK_BOARD.md` (planning-time), agent system prompts (always-on), `phase_X_fixes.md` (verify-time rejection). We're missing the lint/test-time surface — should invest there next.
