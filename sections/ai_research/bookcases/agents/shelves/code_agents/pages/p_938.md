# Code as disposable build artifact (LLM as fuzzy compiler)

**Claim**: Code is a compiled artifact of a well-defined spec. The LLM is a fuzzy compiler. All the harness infrastructure — AGENTS.md, lints, reviewer agents, tests, docs — are effectively *static analysis and optimization passes* on which code is acceptable to generate in the first place.

**Why it matters**: This mental model rewires how you think about model upgrades. Swapping GPT-5.2 → GPT-5.4 is analogous to swapping LLVM → Cranelift in the Rust compiler. Different machine instructions come out, but the *rules* (your harness) still produce acceptable programs. Investment in the harness compounds across every future model release. Investment in any specific line of code depreciates on merge.

**Practical implications**:
- Don't fall in love with implementation; fall in love with constraints
- Model-specific prompting hacks have a half-life; harness structure doesn't
- The spec + harness is the real IP; code is the fall-out
- Deletion and refactor are free — use them

**For SISO**: We're still treating some of our agent output as precious. Healthier stance: the TASK_BOARD.md, the skill definitions, the verifier rulesets — these are durable. The code each worker produces is one possible output of the spec, regeneratable on any model upgrade.
