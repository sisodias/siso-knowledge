# 750-package monorepo with enforced privacy — structure as prompt

**Claim**: Lopopolo's team runs a PNPM workspace with ~750 packages, each isolated by business-logic domain or stack layer. Even without microservices, structuring the repo so that most tasks can be completed within a single subtree is a form of prompt engineering.

**Why it matters**: Code is text. Text the agent sees is context. Organizing that text into enforced scopes (package privacy, import boundaries, domain-local utilities) means the agent builds *transferable* understanding — wherever in the repo it looks, the patterns are the same, so fewer novel tokens need attention per task.

**The corollary — make things the same**:
- One bounded-concurrency helper (not 15)
- One observable/instrumented side-effect wrapper
- One ORM
- One programming language
- One CI script pattern
- One way to add a lint rule

Large-scale refactors to enforce sameness are cheap now (p_929). Ship them.

**For SISO**: Our workspace is the opposite shape — 4 git repos, multiple stacks, domain boundaries are convention-only. For most projects this is fine. But when a single project grows large (isso-dashboard, agency-landing), we should start enforcing package privacy and a single canonical idiom per primitive.
