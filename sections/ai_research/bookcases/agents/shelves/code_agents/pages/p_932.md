# Agent-first repo structure — Codex is the entry point, not a shell

**Claim**: Build the repo so the coding agent is the *outer* process, not the inner one. Don't wrap the app in a shell that gets spawned *into* Codex — write skills that teach Codex how to launch the app, attach observability, invoke DevTools.

**Why it matters**: "Outside-in" design. The human interacts with Codex; Codex interacts with everything else. Every tool in the repo gets a skill that matches this contract. Guardrails slot in cleanly because they attach to the agent's invocation layer, not to an external orchestrator.

**Concrete shape Lopopolo's team uses**:
- Skill to launch the app + local observability stack
- Skill to attach Chrome DevTools via a local daemon
- Custom ESLint ruleset wired into every PNPM package
- Source-code verification tests (structure asserts, not behavior asserts — see p_935)
- Package-privacy enforcement at the dependency layer

**For SISO**: We're already close — `agent_os/hub/skills/` is the entry point contract. Gap: our projects don't uniformly expose "launch app" / "run test suite" / "attach browser" as skills. Worker agents often reinvent these each phase.
