# Persona-based reviewer agents replace synchronous human code review

**Claim**: Instead of blocking PRs on human review, deploy multiple reviewer agents — one per engineering persona (front-end architect, reliability engineer, scalability, product-minded, security). Each reviewer runs on every push and surfaces P2+ issues as PR comments. Humans become one of many reviewers, not the bottleneck.

**Why it matters**: Every engineer on a team has a specialized taste. Writing down what "good" looks like through *their* lens turns one person's expertise into a reviewer agent that every future PR benefits from. The team compounds expertise instead of gatekeeping it.

**Key design choices**:
- **Non-blocking**: author can acknowledge, defer, or reject any comment. Don't let the model get bullied by reviewers.
- **Bias toward merging**: code should be acceptable, not perfect. Drowning in minutia kills throughput.
- **Persona-scoped**: reliability reviewer checks timeouts/retries, security reviewer checks secure interfaces, product reviewer checks UX copy — never one mega-reviewer.

**Contrast with old world**: Code review = one person's opinion serially. New world = every PR gets N expert perspectives in parallel, async, in <60s.

**For SISO Bifrost**: Our `verifier` is a single-purpose tester, not a persona critic. We should split verifier into persona-scoped reviewers per phase: `verifier.types`, `verifier.security`, `verifier.performance`. Each writes to its own feedback doc. Worker only relaunches on merge-blockers.
